# 钉钉机器人接入指南(给帮忙测试的你)

> 你要做的事:让一个 KarvyLoop 里的角色(agent)在钉钉群里能被 @、能回话。
> 全程大约 20 分钟,不用写代码,照着点+复制粘贴就行。

## 你会拿到什么结果

配置完后:在钉钉群里 @ 这个机器人说话 → 绑定的角色用它自己的人格回答你。
别人(没进白名单的)@它 → 只回一句"仅授权用户开放",不会真去跑。

## 前置清单(缺一个就停下来找部署的人)

- [ ] 你在某个**钉钉组织(企业/团队)**里有**管理员或开发者权限**(能进开放平台建应用)
- [ ] 一台正在跑 KarvyLoop 的机器(Windows/Mac/Linux 都行),你知道它的 `config.yaml` 在哪
  (默认 `~/.karvyloop/config.yaml`;Windows 是 `C:\Users\你\.karvyloop\config.yaml`)
- [ ] 那台机器能联网(要连钉钉服务器)

---

## 第一步:钉钉开放平台建应用(约 10 分钟,全网页操作)

1. 打开 **钉钉开放平台**:https://open-dev.dingtalk.com/ ,用钉钉扫码登录。
2. 顶部进 **「应用开发 → 企业内部开发」**,点 **「创建应用」**,名字随便起(比如"小卡测试")。
3. 进应用详情页,左侧找 **「添加应用能力」→ 加「机器人」**。
4. 机器人配置里,**「消息接收模式」选「Stream 模式」**(重点!别选 HTTP 回调,那个要公网服务器)。
5. 左侧 **「版本管理与发布」→ 创建新版本 → 发布**(不发布不生效!最常见漏的就是这步)。
6. 回到组织里某个群,把机器人 **拉进群**(群设置 → 机器人 → 添加)。

## 第二步:拿三样东西

| 东西 | 在哪拿 |
|---|---|
| **ClientID**(也叫 AppKey) | 应用详情页 → 「凭证与基础信息」 |
| **ClientSecret**(AppSecret) | 同上,点"查看"复制 |
| **你的 staffId** | 先随便填一个,第三步跑起来后,你在群里 @机器人 一次,**console 日志会把你的完整 staffId 打出来**,照着改成对的再重启(见排错表) |

## 第三步:在那台机器上装依赖 + 写配置

```bash
pip install "karvyloop[dingtalk]"
```

然后编辑 `~/.karvyloop/config.yaml`,加上这段(注意缩进,YAML 靠缩进吃饭):

```yaml
channels:
  dingtalk:
    enabled: true
    client_id: "ding开头的ClientID"
    client_secret: "你的ClientSecret"
    role: "资料管家"          # 想让哪个角色接钉钉就写哪个(角色面板里的名字)
    allow_senders: ["先随便填"]   # 第二步说了,跑起来后从日志拿真的
```

## 第四步:重启 console,群里 @ 它

```bash
karvyloop console --no-browser --port 8766
```

启动日志里看到 `[dingtalk] 通道已起(Stream 长连接…)` 就是连上了。
然后去钉钉群里 **@机器人 说句话**,比如:"你好,介绍一下你自己"。

## 验收清单(一条条勾)

- [ ] 群里 @机器人,几十秒内它用**角色的口吻**回话(不是系统腔)
- [ ] 接着追问一句(比如"刚才说的再详细点"),它能接住上下文(记得你上一句)
- [ ] 换一个**没进白名单**的同事 @它 → 只收到一句"仅授权用户开放",且不真跑
- [ ] console 的「要我拍什么板」列里,agent 干活冒出的高危卡(比如要发文件、碰工作区外路径)仍然等你拍板,不会自己跑掉

## 排错表

| 症状 | 多半是因为 | 怎么办 |
|---|---|---|
| 日志里有「未装 dingtalk-stream」 | 第三步的 pip 没跑成 | 重跑 `pip install "karvyloop[dingtalk]"`,确认装到同一个 Python 环境 |
| 日志里完全没有 dingtalk 字样 | config.yaml 没生效 | 检查缩进;确认改的是 console 实际读的那份(启动日志会打配置路径) |
| 机器人怎么 @ 都不回 | 应用**没发布**,或没选 Stream 模式 | 回第一步第 4、5 条 |
| 它只回"仅授权用户开放" | allow_senders 里的 staffId 不对 | 看 console 日志里 `[dingtalk] 白名单外 sender 被拒…` 那行,**最后面打印的完整 staffId 就是你该填的**,改配置重启 |
| 回了但不像那个角色 | role 名字写错了 | 去角色面板复制准确的名字 |

## 安全红线(请守住)

- `client_secret` 等于这个机器人的钥匙:**别发群里、别截图、别提交进 git**。
- 测试完不玩了,把 `enabled: true` 改成 `false`(或删掉这段),机器人就安静了。

测完把结果(哪条过了/哪条卡了 + console 日志里 dingtalk 相关的几行)发给部署的人即可。谢谢!
